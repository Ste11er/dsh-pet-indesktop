## 目标与现状

在右键 Agent 联动菜单的 DSH 项后附短状态，让用户直接看出联动是否可用。
当前 [菜单构建函数](../../pet/context_menus/shared.py) 使用注册表的原始标签，不带后缀。
后缀只反映联动连接能力，不等同于 thinking/working 等任务运行状态，也不代表功能开关。

原台账声称已存在的 `pet/dsh_link_status.py::probe_dsh_link`、
`pet/settings_pet_controls.py::DshLinkStatusLabel` 和
`docs/PR-REPORT-DSH-LINK-VISIBILITY-2026-09-29.md` 在本次基线中未找到对应实现/文件。
因此不能直接调用这些接口，也不能把原记载的 7–48 µs 当作本次性能保证。

## 待确认的显示规则

| 场景 | 建议规则 / 待核实点 |
|---|---|
| 连接条件齐备 | 可用「· 已连接」，但须定义实际证据，不能只凭端口开放 |
| 宿主或插件缺失 | 区分哪个组件未安装，短后缀与设置页使用相同语义 |
| 插件已安装但宿主未加载 | 核实后可用「· 需重启 DSH」，不能对所有断线一概建议重启 |
| 未知或探测失败 | 显示明确未知/暂不可用，不能冒充已连接 |
| 开关关闭、用户别名 | 勾选仍代表功能开关；后缀与别名组合方式须通过菜单契约测试 |

上表是设计输入，不冒充缺失模块的原“五态”定义。
