## 目标与范围

让目标 DSH 版本的审批和提问进入桌宠交互队列，点击后回写正确会话与请求，并收到完成回执。
沿用 Pet 侧 `agent-event/v1`、交互队列及幂等语义；新帧字段和回写端点以现场验证为准。
旧版本是否兼容在协议核查阶段明确，不能仅替换 URL 就宣布支持。

当前 [桥接插件](../../integrations/dsh-pet-bridge/index.js) 使用 `/api/events.mux` 与
`server-request`；[回写模块](../../pet/dsh_responder.py) 使用 `/api/respond`。
原台账记载 DSH 0.1.7 契约已变化，但本次未启动目标版本、未验证新契约。
既有语义依据见 [适配器事件契约](../../docs/DSH-BRIDGE-PET-EVENT-CONTRACT-2026-09-02.md)。

## 验收与验证

| 场景 | 通过标准 |
|---|---|
| 同意、拒绝、问题选项 | 回写关联正确；服务端确认后关闭对应提醒 |
| 多会话相同局部 ID | 按协议要求的完整关联键隔离，不串请求 |
| mux 重放、重复 resolved、重复点击 | 不重复入队或产生重复业务提交 |
| DSH 短断线、重启、过期请求 | 与 03 的失联/退出语义一致；恢复后对账，不回写失效请求 |
| 回写失败 | 用户能理解失败；保留或恢复可重试状态，不能静默丢提醒 |

已有入口：`tests/test_bridge_interaction_dedup.js`、`tests/test_bridge_question_callid.js`、
`tests/test_bridge_user_action_guard.js`、`tests/test_agent_link.py`、`tests/test_agent_link_threads.py`。
新增协议与 responder 用例需跟随步骤 3 落地。执行示例：

```bash
node tests/test_bridge_interaction_dedup.js
node tests/test_bridge_question_callid.js
QT_QPA_PLATFORM=offscreen .venv/bin/python -m pytest -q tests/test_agent_link.py tests/test_agent_link_threads.py tests/test_dsh_state.py
```

至少采集每类交互 10 次；分别记录事件到气泡、点击到回执的 p50/p95，断线重连 10 轮，
稳态 10 分钟的连接/线程数与 RSS。数字由执行时实测，不能用本计划估时代替。
线程和跨域改动须全量与受影响时序族满载复跑；真实 DSH 无法运行时保留探针结果，不标端到端通过。
